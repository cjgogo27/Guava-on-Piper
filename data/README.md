# Data card: compact evidence release v0.1

**Purpose:** numerical reproduction and diagnosis of a Piper migration, not policy training.

## Contents and units

- `evaluation`: per-task counts for baseline/SFT,450 scheduled per model. One SFT process abort counts as zero success in the450 denominator;449 ordinary completed SFT results. Complete-case paired counts cover449, not450.
- `collection`: schema audit of1041 training records and a completed single SFT-run summary. This is metadata, not the training corpus.
- `perception/g1.json`:48 planned independent layouts,7 common initial rejects; same-state method comparisons.8 layout repeats are diagnostic, not extra independent samples. Whole-sequence scoring includes common setup contact.
- `perception/g2_calibration.json`:16 planned layouts across4 calibration identities,5 initialization rejects,11 executed layouts×8arms=88. The identity split is not a held-out test. Rejected initial states contribute zero for all methods; none is silently replaced.
- `verification/held_detection.json`:32 independent layouts and4 repeats.25operational held positives and7 negatives. The label is sustained vertical target rise in simulation, not a causal attachment proof. Contact qualification is reported separately.
- `diagnostics`: collision-candidate transformation provenance; small-case findings, not a universal safety guarantee.
- `provenance`: original summary SHA256/byte counts plus the public release manifest.

## Annotation and quality

Original task reward, physical qualification and interpretation/visual confirmation are distinct. Historical training selection bypassed final-review approval; the recorded1041 set contained200 approved,724 unreviewed,90 needs-review and27 rejected labels. These metadata are retained as a limitation, not changed to “approved.” No such trajectories are released as training-ready here.

The final perception scorer includes shared setup in its contact window. One G1 layout with2.917mm common-prefix penetration is unqualified for every arm. Earlier after-parent counts must not replace the final whole-sequence counts.

## Availability and Hugging Face decision

The numerical release and four images are small enough for ordinary Git. No Hugging Face dataset is needed for these artifacts. Full SFT assets were approximately6.55GB; the separate32-layout raw-state experiment approximately3.95GB. Those are **different datasets**, with models/meshes, access terms, native image dependencies and mixed review labels. They are not silently concatenated or uploaded.

The visual site adds3 small, compressed own historical videos (approximately1MB combined), with complete source timelines at4×. All three retain their original reward labels and pending physical-review status; they are not new controlled-study evidence. Video/frame source identities are in `site/assets/video_manifest.json`. These do not change the sample counts in the numeric release.

Raw dynamics states, full native trajectories, videos, model binaries and checkpoints are **not public in this release**. This restricts external physical replay and re-verification. A future Hugging Face release needs an explicit asset/license inventory, source/parent dependency closure, documented partitions and a clear mixed-quality label policy. We make no claim that these prerequisites have already been completed.

## Privacy, transformations and licenses

Public summaries are selected/redacted from retained originals. Absolute server paths, process identifiers and unrelated operational records are removed. Original summary hashes are listed; edited exports have separate hashes. Numeric evidence is CC BY4.0; external assets and diagnostic images are excluded as described in `NOTICE.md`.

No personal data or real-robot recordings are intended. Seeds and task identifiers are included. This is a single project/robot/simulator case study, not a representative sample of all embodied systems.
